# WORLD EMPIRES — MVP Implementation Roadmap

Основа: `world-empires-mvp-architecture.md`.
Движок: Godot 4, GDScript only.
Правило: после каждой итерации проект запускается, не падает, демонстрирует прирост функциональности.

---

## Итерация 0 — Bootstrap проекта

**Цель:** пустой, но валидный Godot-проект с зафиксированной структурой папок.

**Системы:** нет.

**Файлы/классы:**
- `project.godot`
- Папки: `core/`, `world/`, `economy/`, `technology/`, `military/`, `diplomacy/`, `ai/`, `ui/`, `data/`, `tests/` (пустые, с `.gdignore`/README-заглушками)
- `main.tscn` + `main.gd` — пустая сцена

**Зависимости:** нет.

**Что работает:** проект открывается в редакторе, запускается, чёрный экран без ошибок в консоли.

**Критерии готовности:** `godot --headless --quit` завершается с кодом 0.

**Тесты:** нет.

**НЕ реализовывать:** ничего игрового.

## Итерация 1 — GameTime + Season Tick (скелет)

**Цель:** работающий календарь и заготовка Season Tick без систем внутри.

**Системы:** `GameTime`.

**Файлы/классы:**
- `core/game_time/game_date.gd` — `GameDate {year:int, season:int, turn_number:int}`
- `core/i_game_system.gd` — базовый класс с `on_season_tick(state)`, `on_command(cmd)`
- `core/game_time/season_tick_manager.gd` — autoload, хранит `Array[IGameSystem]`, метод `advance_season()`
- `ui/debug_hud.gd/tscn` — label с датой + кнопка "Next Season"

**Зависимости:** Итерация 0.

**Что работает:** нажатие кнопки продвигает дату (Spring 1000 → Summer 1000 → … → Spring 1001).

**Критерии готовности:** переход Winter→Spring корректно увеличивает `year`.

**Тесты:** unit-тест rollover сезона/года.

**НЕ реализовывать:** регистрация реальных систем, WorldState.

## Итерация 2 — EventBus, RNG, EntityID

**Цель:** инфраструктура коммуникации и детерминизма.

**Системы:** `EventBus`, `GameRNG`.

**Файлы/классы:**
- `core/event_bus/event_bus.gd` — autoload, `emit(event_name, payload)`, `subscribe(event_name, callback)`
- `core/rng/deterministic_rng.gd` — autoload `GameRNG`, обёртка над `RandomNumberGenerator` с явным `seed`
- `core/entity_ids/id_types.gd` — типизированные алиасы (`CountryID`, `RegionID`, `CityID`, `ArmyID`, `GeneralID` = `String`/`int`)

**Зависимости:** Итерация 0.

**Что работает:** тестовая кнопка эмитит событие, debug-лог его ловит; два запуска с одинаковым seed дают одинаковую последовательность чисел (видно в логе).

**Критерии готовности:** RNG-детерминизм подтверждён.

**Тесты:** unit-тест `GameRNG` (совпадение последовательностей), unit-тест `EventBus` (emit → subscriber получает payload).

**НЕ реализовывать:** WorldState, игровые данные.

## Итерация 3 — WorldState + Save/Load (заготовка)

**Цель:** единый источник истины мира + подтверждённый цикл сохранения пустого состояния.

**Системы:** `WorldState`, `SaveSystem`.

**Файлы/классы:**
- `world/world_state.gd` — autoload `WorldState`: `game_date`, `rng_seed`, `countries:{}`, `regions:{}`, `cities:{}`, `armies:{}` (все пустые)
- `core/save_system/save_file_format.gd` — заголовок `{save_version, game_version, metadata}`
- `core/save_system/save_system.gd` — `save_to_json(path)`, `load_from_json(path)`

**Зависимости:** Итерация 1 (`GameDate` внутри), Итерация 2 (`rng_seed`).

**Что работает:** "New Game" создаёт `WorldState` с датой и seed; Save пишет JSON; Load восстанавливает — дата/seed совпадают после релоада.

**Критерии готовности:** round-trip save→load сохраняет `game_date` и `rng_seed` побайтово идентично по значению.

**Тесты:** интеграционный тест save→load→compare.

**НЕ реализовывать:** реальные страны/регионы/армии — только структура словарей.

---

## Итерация 4 — Command System (скелет)

**Цель:** единый путь изменения мира для игрока и AI.

**Системы:** `CommandBus`.

**Файлы/классы:**
- `core/command_system/command.gd` — база: `source_country`, `timestamp`, `validate(state)->bool`, `execute(state)->CommandResult`
- `core/command_system/command_result.gd`
- `core/command_system/command_bus.gd` — autoload: `submit(cmd)` → validate → execute → `EventBus.emit`
- Тестовая команда: `core/command_system/commands/noop_command.gd`

**Зависимости:** Итерация 3 (`WorldState`), Итерация 2 (`EventBus`).

**Что работает:** отправка тестовой команды меняет `WorldState` и генерирует событие, видно в debug-логе.

**Критерии готовности:** невалидная команда отклоняется с причиной; валидная — применяется и логируется.

**Тесты:** unit-тест `validate()` reject-путь, unit-тест `execute()` success-путь.

**НЕ реализовывать:** игровые команды (движение, постройка и т.д.).

## Итерация 5 — Карта: регионы одного континента

**Цель:** отрисованный континент из 150–300 регионов с графом соседства.

**Системы:** `MapData`.

**Файлы/классы:**
- `world/map/region.gd` — `Region {id, neighbors[], terrain, polygon/center, country_id=null, population=0, resources={}}`
- `data/regions/regions.json` — данные континента (сгенерированы вручную/скриптом-генератором один раз)
- `world/map/map_view.gd/tscn` — рендер регионов (Node2D-полигоны, placeholder-цвет)
- `world/map/camera_controller.gd` — pan/zoom

**Зависимости:** Итерация 3 (`WorldState.regions`).

**Что работает:** запуск игры показывает карту континента; клик по региону подсвечивает его и печатает id/соседей в debug-панель.

**Критерии готовности:** все регионы отрисованы; граф соседства симметричен (если A сосед B, то B сосед A); количество регионов в диапазоне 150–300.

**Тесты:** unit-тест симметрии соседства, unit-тест диапазона количества регионов.

**НЕ реализовывать:** страны, границы, города, население — регионы серые, "ничьи".

## Итерация 6 — Страны и границы

**Цель:** 4–8 государств с территорией, игрок выбирает одно на старте.

**Системы:** `CountrySystem`.

**Файлы/классы:**
- `world/countries/country.gd` — `Country {id, name, flag, color, capital_region, regions[], treasury, technology_level, researched_technologies, stability, power_score, is_player_controlled}`
- `data/countries/countries.json` — 4–8 государств, стартовые регионы
- `world/countries/border_renderer.gd` — перекраска регионов по `country_id`, перерасчёт границ по событию смены владельца
- `ui/country_select_screen.gd/tscn` — экран выбора страны перед стартом

**Зависимости:** Итерация 5 (регионы), Итерация 3 (`WorldState.countries`).

**Что работает:** экран выбора → карта окрашена по странам, страна игрока выделена отдельно.

**Критерии готовности:** каждый регион имеет валидный `country_id`; каждая страна владеет ≥1 регионом; столица находится среди своих регионов.

**Тесты:** integrity-тест (аналог части 4.87 ТЗ): валидность владельцев/столиц.

**НЕ реализовывать:** численность населения, экономику, армию.

## Итерация 7 — SeasonTickManager: реальная регистрация систем

**Цель:** пайплайн Season Tick с фиксированным порядком, пока со stub-системами.

**Системы:** обновлённый `SeasonTickManager`.

**Файлы/классы:**
- `core/game_time/tick_order.gd` — фиксированный список порядка (`ValidateActions, Movement, Battles, Supply, Production, Population, Economy, Diplomacy, AI, WorldUpdate, VictoryCheck, Notifications, SaveCheck`)
- Правка `season_tick_manager.gd`: вызов `on_season_tick()` у всех зарегистрированных систем в этом порядке

**Зависимости:** Итерации 1, 3, 4.

**Что работает:** "Next Season" продвигает реальный `WorldState.game_date`, пустой пайплайн проходит без ошибок, событие `NEW_SEASON` эмитится.

**Критерии готовности:** порядок вызовов совпадает с разделом 6 спецификации (проверяется через mock-системы, фиксирующие порядок вызова).

**Тесты:** тест последовательности вызовов через mock `IGameSystem`.

**НЕ реализовывать:** реальную логику экономики/военных/дипломатии внутри шагов — только stub-вызовы.

## Итерация 8 — Население (базовое, привязано к регионам)

**Цель:** регионы получают растущее население.

**Системы:** `PopulationSystem`.

**Файлы/классы:**
- Правка `region.gd`: поле `population` уже есть (Итерация 5), теперь используется
- `world/population/population_system.gd` (`IGameSystem`): простая формула роста (`+X%` за сезон, с капом)

**Зависимости:** Итерация 5 (`Region`), Итерация 7 (регистрация в тике).

**Что работает:** население видно при клике на регион, растёт каждый сезон.

**Критерии готовности:** население никогда не отрицательное; темп роста соответствует константе конфига.

**Тесты:** unit-тест формулы роста за N тиков.

**НЕ реализовывать:** миграцию, демографические группы, культуру.

## Итерация 9 — Ресурсы + базовая экономика (казна)

**Цель:** казна страны меняется каждый сезон на основе дохода/расходов.

**Системы:** `EconomySystem`.

**Файлы/классы:**
- `economy/resources/resource_types.gd` — enum: `Gold, Food, Industry, Science, Manpower`
- `economy/budget/economy_system.gd` (`IGameSystem`): суммирует доход регионов → `country.treasury`, вычитает фиксированные расходы
- `ui/panels/economy_panel.gd/tscn` — казна, доход, расход

**Зависимости:** Итерация 6 (`Country`), Итерация 8 (население влияет на доход), Итерация 7.

**Что работает:** казна видимо меняется каждый сезон; UI-панель обновляется через подписку на событие.

**Критерии готовности:** формула детерминирована, воспроизводима; нет `NaN`/бесконечных значений.

**Тесты:** unit-тест `economy_system.on_season_tick()` на mock-стране — ожидаемая дельта казны.

**НЕ реализовывать:** производственные цепочки, здания, торговлю.

## Итерация 10 — Производство (здания, упрощённо)

**Цель:** игрок может строить здания, влияющие на вывод города.

**Системы:** `ProductionSystem`, минимальный `City`.

**Файлы/классы:**
- `world/cities/city.gd` — `City {id, region_id, level, population, industry, food, gold, manpower}`
- `economy/production/building.gd` — ресурс: `id, cost, output_modifiers`
- `economy/production/production_system.gd` (`IGameSystem`): применяет эффекты зданий к выводу города
- `core/command_system/commands/build_building_command.gd`
- 2–3 типа зданий в данных (ферма, фабрика)

**Зависимости:** Итерация 4 (Command), Итерация 9 (Economy), Итерации 5/6 (Region/Country).

**Что работает:** игрок ставит здание в очередь через UI, через N сезонов оно достраивается, вывод растёт.

**Критерии готовности:** очередь строительства переживает тики; событие завершения эмитится один раз; эффект применяется ровно один раз.

**Тесты:** unit-тест прогресса очереди и завершения по истечении срока.

**НЕ реализовывать:** более 2–3 типов зданий, специализацию городов.

**Цель:** 10–15 технологий, исследование за очки науки.

**Системы:** `TechnologySystem`.

**Файлы/классы:**
- `technology/technology.gd` — ресурс: `id, cost, prerequisites[], effects[]`
- `technology/technology_system.gd` (`IGameSystem`): накопление науки, обработка `ResearchTechnologyCommand`
- `data/technologies/*.json` — 10–15 записей
- `core/command_system/commands/research_technology_command.gd`
- `ui/panels/technology_panel.gd/tscn`

**Зависимости:** Итерация 9 (ресурс Science), Итерация 4, Итерация 7.

**Что работает:** игрок выбирает технологию, наука копится, при достижении стоимости технология разблокируется, эффект (например, `+production%`) применяется.

**Критерии готовности:** пререквизиты соблюдаются; повторное исследование отклоняется; эффекты корректно складываются.

**Тесты:** unit-тест валидации пререквизитов, unit-тест применения эффекта.

**НЕ реализовывать:** полное дерево из ТЗ, эпохи.

## Итерация 12 — Военные: юниты, армии, генералы (данные, без боя)

**Цель:** создание армий с юнитами и генералами, отображение на карте.

**Системы:** `MilitaryDataLayer` (без боя и движения).

**Файлы/классы:**
- `military/units/unit_type.gd` — ресурс: `id, manpower, attack, defense, speed`
- `data/units/*.json` — 3–5 типов юнитов (пехота, кавалерия, артиллерия)
- `military/armies/army.gd` — `Army {id, country_id, units[], general_id, position, supply, movement_target, order}`
- `military/generals/general.gd` — `General {id, attack, defense, tactics, logistics, command, experience, army_id}`
- Команды: `recruit_unit_command.gd`, `create_army_command.gd`, `assign_general_command.gd`
- `ui/panels/army_panel.gd/tscn`

**Зависимости:** Итерация 9 (manpower), Итерация 6 (Country), Итерация 4.

**Что работает:** игрок рекрутирует юниты в городе, формирует армию, назначает генерала, армия появляется маркером на карте.

**Критерии готовности:** армия обязательно привязана к валидной стране; рекрутирование не превышает доступный manpower; генерал назначен ровно одной армии.

**Тесты:** unit-тест списания manpower при рекруте, unit-тест валидации создания армии.

**НЕ реализовывать:** движение, снабжение по-настоящему, бой, способности генералов.

## Итерация 13 — Движение армий

**Цель:** армия перемещается по графу регионов, 1 регион за сезон.

**Системы:** `MovementSystem`.

**Файлы/классы:**
- `military/armies/pathfinding.gd` — BFS по соседям региона
- `military/armies/movement_system.gd` (`IGameSystem`): обработка `MoveArmyCommand`, продвижение армии на 1 регион за тик

**Зависимости:** Итерация 12 (`Army`), Итерация 5 (соседство регионов), Итерация 7.

**Что работает:** игрок выбирает армию, кликает регион-цель, армия видимо двигается по 1 региону за сезон, путь отображается на карте.

**Критерии готовности:** армия не может зайти в невалидный регион (нет такого соседа); движение продвигается ровно на 1 регион за тик.

**Тесты:** unit-тест pathfinding (валидная цепочка соседей), unit-тест продвижения на 1 регион за тик.

**НЕ реализовывать:** переход через море (моря нет в MVP), учёт снабжения при движении.

## Итерация 14 — Дипломатия: базовая (война/мир)

**Цель:** объявление войны и заключение мира между странами.

**Системы:** `DiplomacySystem`.

**Файлы/классы:**
- `diplomacy/diplomacy_graph.gd` — `Dictionary<CountryPair, RelationState{is_at_war}>`
- `diplomacy/diplomacy_system.gd` (`IGameSystem`, преимущественно реактивная)
- `core/command_system/commands/declare_war_command.gd`, `propose_peace_command.gd` (мир — автопринятие в MVP, без переговоров)
- `ui/panels/diplomacy_panel.gd/tscn`

**Зависимости:** Итерация 6 (`Country`), Итерация 4.

**Что работает:** игрок объявляет войну соседу, состояние войны видно в UI, армии теперь могут атаковать регионы этой страны.

**Критерии готовности:** нельзя объявить войну повторно уже воюющей паре; мир снимает состояние войны и останавливает бои.

**Тесты:** unit-тест переключения состояния войны, unit-тест запрета самообъявления войны.

**НЕ реализовывать:** доверие, репутацию, союзы, блоки, casus belli.

## Итерация 15 — Бой: обнаружение контакта + автобой

**Цель:** армии воюющих сторон, встретившись в регионе, автоматически сражаются.

**Системы:** `CombatSystem`.

**Файлы/классы:**
- `military/combat/contact_detector.gd` — после разрешения движения проверяет совпадение позиций вражеских армий
- `military/combat/autobattle_resolver.gd` — формула из спецификации: `Attack + Tech + Experience + GeneralBonus - Defense - TerrainBonus`, разрешение боя, потери, победитель
- `military/combat/battle_report.gd` — данные отчёта
- `ui/panels/battle_report_panel.gd/tscn`

**Зависимости:** Итерация 13 (позиции после движения), Итерация 12 (Army/General), Итерация 14 (бой только при войне), Итерация 7 (шаг `ResolveBattles`).

**Что работает:** две вражеские армии встречаются в регионе → автобой → потери применены → победитель занимает регион → отчёт показан игроку.

**Критерии готовности:** бой не уничтожает обе стороны одновременно некорректно; смена владельца региона только при решающей победе; потери корректно списываются со стеков юнитов; полное уничтожение армии не вызывает краш.

**Тесты:** unit-тест резолвера с фиксированными входными данными (детерминированный результат при одинаковом seed), unit-тест смены владельца региона при победе, unit-тест удаления армии при полном уничтожении.

**НЕ реализовывать:** ручной бой, фланги, укрепления, критические удары.

---

## Итерация 16 — AI: стратегический, экономический, военный слои

**Цель:** 4–8 AI-стран самостоятельно действуют каждый сезон.

**Системы:** `AIController` (`StrategicAI`, `EconomicAI`, `MilitaryAI`).

**Файлы/классы:**
- `ai/strategic/strategic_ai.gd` — оценка расширяться/обороняться/нейтралитет
- `ai/economic/economic_ai.gd` — распределение бюджета по фиксированным профилям, выбор технологии
- `ai/military/military_ai.gd` — защита столицы, атака слабого соседа при явном перевесе, отступление при потере >50% армии
- `ai/ai_controller.gd` — оркестрирует три слоя для каждой AI-страны каждый сезон, отправляет команды через `CommandBus`

**Зависимости:** все предыдущие системы (AI читает `WorldState`, отправляет команды тем же путём, что и игрок).

**Что работает:** AI-страны строят, исследуют, рекрутируют, двигают армии, объявляют войну/мир без участия игрока; игрок может просто нажимать "Next Season" и наблюдать изменение мира.

**Критерии готовности:** ни одна AI-команда не проходит с невалидными данными (валидируется тем же путём, что и у игрока); AI не зацикливается; AI соблюдает те же ресурсные ограничения.

**Тесты:** интеграционный тест — 50 сезонов headless только с AI, без падений, без ухода казны в `-infinity`, минимум одна война возникает за серию прогонов.

**НЕ реализовывать:** тактический AI (бой = автобой по формуле), Fog of War, разведку.

## Итерация 17 — Победа/поражение

**Цель:** кампания корректно завершается.

**Системы:** `VictorySystem`.

**Файлы/классы:**
- `core/victory/victory_system.gd` (`IGameSystem`, последний шаг тика): победа — игрок контролирует весь континент; поражение — 0 регионов/нет столицы
- `ui/end_screen.gd/tscn`

**Зависимости:** Итерация 6, Итерация 7 (последний шаг тика), все территориальные системы.

**Что работает:** игра корректно завершается при выполнении условия, показывает экран с базовой статистикой (территория %, достигнутая дата).

**Критерии готовности:** после завершения новые сезоны/команды не обрабатываются.

**Тесты:** unit-тест проверки победы (единственный владелец), unit-тест проверки поражения (0 регионов у игрока).

**НЕ реализовывать:** победу через альянс, частичную победу, экран истории кампании.

## Итерация 18 — Save/Load: полная интеграция

**Цель:** сохранение/загрузка полного состояния мира на любой стадии игры.

**Системы:** расширенный `SaveSystem`.

**Файлы/классы:**
- `core/save_system/world_state_serializer.gd` — сериализация всех структур: страны, регионы, города, армии, дипломатия, генералы, состояние технологий
- `ui/save_load_menu.gd/tscn`

**Зависимости:** буквально всё выше — сериализуется каждая структура данных, существующая на этот момент.

**Что работает:** сохранение в середине партии, выход, перезапуск, загрузка — игра продолжается идентично (армии в движении, активные войны, исследование в процессе, состояние AI).

**Критерии готовности:** round-trip save→load даёт семантически идентичный `WorldState`; детерминизм подтверждён — N тиков после загрузки дают тот же результат, что и продолжение без перезагрузки при одинаковом seed и командах.

**Тесты:** интеграционный тест полного save→load→сравнение всех словарей; regression-тест детерминизма.

**НЕ реализовывать:** облачные сохранения, разделение static/dynamic данных (оптимизация post-MVP).

## Итерация 19 — UI: сборка HUD + уведомления

**Цель:** единый связный экран вместо разрозненных панелей.

**Файлы/классы:**

- `ui/hud.gd/tscn` — объединяет `map_view` + все панели + уведомления по layout из спецификации (раздел 24.76, упрощённо)

**Зависимости:** все системы, генерирующие события выше.

**Что работает:** один экран: карта, верхняя панель (дата/казна/пауза), боковые панели, лента уведомлений.

**Критерии готовности:** ни одно критическое событие не теряется молча; UI не блокирует ввод (немодальные уведомления).

**Тесты:** ручной чек-лист, автотесты не требуются.

**НЕ реализовывать:** анимации, кастомизацию UI, горячие клавиши сверх необходимого минимума.

## Порядок ядра (явно зафиксирован)

```
WorldState (3)
   ↓
EventBus (2) — параллельно с WorldState
   ↓
Command System (4)
   ↓
SeasonTickManager: скелет (1) → регистрация систем (7)
   ↓
Карта/регионы (5)
   ↓
Страны (6)
   ↓
Экономика (9) ← Население (8)
   ↓
Армия (12) → Движение (13)
   ↓
Дипломатия (14)
   ↓
Бой (15)
   ↓
AI (16) — последним, т.к. читает все системы
   ↓
Победа/поражение (17)
   ↓
Save/Load полный (18)
```

AI сознательно идёт после боя и дипломатии — он должен отправлять те же команды, что уже провалидированы игроком в предыдущих итерациях. Save/Load полный — последним перед UI-полировкой, т.к. сериализовать нужно финальный набор структур, а не переписывать сериализатор при каждой новой системе.
